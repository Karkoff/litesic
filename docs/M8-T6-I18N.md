## C. Arquitetura e contratos

`src/i18n.h/.cpp`: serviço C++17 independente de HWND e áudio, sem bibliotecas novas.
Cada instância mantém somente inglês e catálogo ativo. A fachada global usa
`CRITICAL_SECTION` para serializar consultas de erros de workers e mudanças de idioma.
Não chamar esta API no callback de áudio. As consultas devolvem strings por valor.

| Operação | Contrato |
|---|---|
| `Parse` / `Read` | UTF-8 estrito, limite 1 MiB, rejeição de duplicatas, vazios, controles, escapes e parâmetros inválidos; erro explícito |
| `Validate` | IDs conhecidos, parâmetros compatíveis, seis formas por família plural e cobertura integral quando solicitada |
| `Select` | Resolve código; lê e valida antes de substituir; erro preserva catálogo anterior; inglês incorporado independe de arquivos |
| `Install` | Catálogo completo em produção; parcial apenas por API explícita para extensões/testes de fallback |
| `Text` | Catálogo ativo → inglês; ID desconhecido produz diagnóstico debug e mensagem inglesa segura |
| `Format` | Parâmetros nomeados exatos; inserção única sem interpretar novamente o conteúdo do usuário |
| `Count` | Contagens inteiras sem sinal; categorias zero/one/two/few/many/other; fallback usa também gramática inglesa |
| `Unload` | Libera ativo e volta ao inglês; incrementa geração |
| `Generation` | Invalidação de recursos tipográficos e preparação para notificações T7 |

Catálogos: `locales/<código>/messages.tsv`, uma chave ASCII e TAB seguido de texto
UTF-8 por linha; `#` inicia comentário; `\n` representa quebra e `\\` uma barra.
Inglês incorporado em `src/i18n_english.h`, gerado do catálogo en-US. O caminho
é calculado a partir de `GetModuleFileNameW`; nunca depende do diretório corrente.
`make all/test` copia `locales` ao lado do binário para desenvolvimento/testes.
Isso não implementa a distribuição da M10.

## F/G. Unicode, RTL e fontes

Decodificação usa `MultiByteToWideChar(CP_UTF8, MB_ERR_INVALID_CHARS)`; Win32
recebe UTF-16 pelas APIs W. Não há passagem pela code page ANSI, corte de bytes
UTF-8 nem manipulação manual de pares substitutos para truncamento visual.
Testes incluem combinantes, emoji suplementar, UTF-8 inválido e UTF-16 inválido
na instalação direta. DirectWrite realiza shaping, bidi, medição e reticências;
GDI usa `DrawTextW`, fontes por script e flags RTL nos componentes migrados.

Latino/cirílico mantêm tipografia do tema. Scripts usam fontes nativas:
Meiryo (ja), Microsoft YaHei (zh-CN), Microsoft JhengHei (zh-TW), Malgun Gothic
(ko), Tahoma (ar), Mangal (hi). Fontes não são distribuídas; fallback nativo
depende das fontes/pacotes do Windows instalado. O papel digital permanece
inalterado. Recursos são reutilizados e invalidados por geração de tema/idioma.
As 36 paletas, tamanhos e geometria dos controles são preservados.

Árabe: texto próprio com direção RTL e alinhamento inicial à direita;
mensagens parametrizadas envolvem argumentos em LRE/PDF para manter números
e caminhos compostos. Valores puramente técnicos preservam direção LTR;
metadados em rolagem preservam a orientação do componente com runs bidi nativos.
Controles de transporte, EQ e visualizador não são espelhados. Isso não é
certificação de RTL integral: bidi complexo em conteúdo arbitrário e diálogos
do sistema continuam sujeitos à validação prática em cada Windows.

APIs novas mantêm alvo Windows 7. Fontes e fallback seguem o sistema, sem
depender de `IDWriteFontFallback` moderno. Referências primárias consultadas:
[SetReadingDirection](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nf-dwrite-idwritetextformat-setreadingdirection),
[Font enumeration](https://learn.microsoft.com/en-us/windows/win32/directwrite/font-enumeration),
[MultiByteToWideChar](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-multibytetowidechar).
Não foi realizada certificação prática de Windows 7/8/8.1/10 nesta tarefa.

## J. Custo incremental

O teste mede construção do fallback, média de uma seleção de cada catálogo,
Private Bytes antes/depois do fallback e depois de aquecimento/1.980 trocas,
além do payload de chaves e UTF-16 retido. Só ativo + inglês ficam residentes;
nenhum arquivo é lido durante desenho. Consultas não recriam recursos gráficos.
Os números por variante constam nas evidências. Payload exclui overhead do
alocador/árvore; Private Bytes inclui ruído do processo. O limite de crescimento
pós-aquecimento é 512 KiB. São medições incrementais do serviço, não comparação
de startup completo com o executável anterior nem auditoria global de desempenho.

## K/M. Limites e próximas integrações

T7 deve consumir preferências Windows, criar seletor e persistência no mecanismo
existente e emitir atualização às janelas, menus, títulos nativos, edit de pesquisa,
diálogo de informações aberto e buffers dos tooltips existentes. Canvas já observa
geração; valores retornados são próprios, sem ponteiros para catálogos descarregados.
O comando `--validation --locale=<código>` é fixture de teste isolado, sem menu
ou preferência de produto. Não foi criada detecção automática Windows nesta etapa.

T8 deverá ampliar textos explicativos, hover/saída, acessibilidade e atualização
dos tooltips. Os tooltips atuais já consultam o catálogo na criação, mas seus
buffers não são renovados automaticamente em uma troca programática. A revisão
linguística humana e validação de RTL complexo permanecem explícitas.

Para adicionar idioma: cadastrar metadados em `Languages`, criar TSV completo
com os IDs ingleses, definir resolução/plurais/fontes, atualizar a lista aprovada
do verificador e da fixture, rodar `python scripts/i18n_catalogs.py --source`,
as quatro variantes e revisão visual/linguística. Ao alterar inglês, executar
`python scripts/i18n_catalogs.py --generate` e revisar o header gerado.
