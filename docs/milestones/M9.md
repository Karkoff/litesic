## Objetivo original

Confirmar que o `.exe` gerado roda sem dependências externas em Windows 7
SP1 (32 e 64 bits), além de Windows 8/8.1/10/11, e corrigir qualquer
divergência encontrada.

## Tarefas

- [ ] **M9-T1 — Checar DLLs importadas**
  - **Arquivos:** nenhum (verificação).
  - **O que fazer:**
    - Rodar `objdump -p build/LiteSic.exe | grep "DLL Name"` nas builds
      Release 32 e 64 bits.
    - Confirmar que só aparecem DLLs de sistema (`KERNEL32.dll`,
      `USER32.dll`, `GDI32.dll`, `msvcrt.dll`, `ole32.dll`,
      `COMDLG32.dll`, `SHELL32.dll`, `WINMM.dll`/`ksuser.dll` se
      aplicável para áudio, etc.) — nenhuma DLL do MinGW/runtime C++
      (`libgcc_s_*.dll`, `libstdc++-6.dll`, `libwinpthread-1.dll`) deve
      aparecer, confirmando que o link estático (`-static` do M0-T3)
      funcionou.
  - **Testes:** o próprio comando é o teste; se alguma DLL do MinGW
    aparecer, ajustar flags de link no `Makefile` até sumir.
  - **Pronto quando:** saída do `objdump` só lista DLLs de sistema, nas
    duas arquiteturas.

- [ ] **M9-T2 — Rodar em VM Windows 7 SP1 (32 e 64 bits)**
  - **Arquivos:** nenhum (validação).
  - **O que fazer:**
    - Preparar VM (VirtualBox ou Hyper-V) com Windows 7 SP1, uma de
      32 bits e outra de 64 bits.
    - Copiar o `.exe` correspondente (sem instalar nada) e verificar:
      - Abre sem pedir DLL ausente.
      - Toca MP3, FLAC, OGG e WAV.
      - EQ altera o som.
      - Arrastar e soltar arquivos na lista funciona.
      - Dispositivos de áudio USB/HDMI (se disponíveis na VM/host) são
        reconhecidos.
      - Teclas de mídia e atalhos funcionam.
      - Instância única funciona.
  - **Testes:** checklist manual acima, uma vez por arquitetura.
  - **Pronto quando:** checklist completo sem falhas nas duas VMs.

- [ ] **M9-T3 — Registrar e corrigir divergências**
  - **Arquivos:** variam conforme o problema encontrado.
  - **O que fazer:**
    - Para cada item que falhar em M9-T2, abrir uma tarefa específica
      (registrar aqui mesmo, como sub-itens, ou em issues do
      repositório), investigar causa raiz (normalmente: API que não
      existe no Win7, comportamento diferente de DPI/tema, dispositivo de
      áudio não suportado pelo backend escolhido) e corrigir.
    - Se a causa não for óbvia, consultar MCP context7 (comportamento de
      API específica em Windows 7) e/ou MCP github (como outros projetos
      lidam com a mesma divergência) antes de tentar workarounds às
      cegas.
  - **Testes:** repetir o checklist do M9-T2 após cada correção.
  - **Pronto quando:** nenhuma divergência conhecida restante entre
    Win7/8/10/11.
