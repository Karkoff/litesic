# M2 — Tocar um arquivo

**Depende de:** M1
**Checkpoint visual:** 🖥️ sim — abre um arquivo pelo diálogo do Windows e
toca, com play/pause/stop funcionando.

## Objetivo

Ligar o motor de áudio (miniaudio) à janela do M1. Ao final desta
milestone o app já é "um player" no sentido mínimo: escolhe um arquivo e
ele toca.

## Tarefas

- [x] **M2-T1 — Inicializar miniaudio (engine + device)**
  - **Arquivos:** `src/audio.h`, `src/audio.cpp`, `src/miniaudio_impl.c`
    (de M0), `src/ma_config.h`.
  - **O que fazer:**
    - `ma_config.h`: define as macros de configuração do miniaudio antes do
      include (que decoders habilitar, `MA_NO_...` para desligar o que não
      for usado, reduzindo tamanho do binário).
    - `audio.h`: interface pública do motor —
      `bool Audio_Init();`, `void Audio_Shutdown();`, sem expor tipos do
      miniaudio no header (opaco), para o resto do app não depender
      diretamente da biblioteca.
    - `audio.cpp`: inicializa `ma_engine` (que já gerencia device +
      resampler + mixing), com `ma_engine_config` configurado para WASAPI
      como backend preferido — miniaudio já faz fallback automático para
      DirectSound/WinMM se WASAPI não estiver disponível (Windows 7 tem
      WASAPI desde o lançamento, então normalmente não deveria cair no
      fallback, mas o código não deve assumir isso).
    - Tratar falha de inicialização (nenhum dispositivo de áudio, device
      ocupado) sem crashar — log e retorno `false` para `Audio_Init`.
  - **Testes:** nenhum automatizado direto (depende de hardware de áudio
    real ou de um device nulo/loopback). Validar manualmente que
    `Audio_Init()` retorna sucesso na máquina de desenvolvimento.
  - **Pronto quando:** `Audio_Init()` inicializa sem erro na máquina local,
    `Audio_Shutdown()` libera tudo sem vazamento (checar com um teste
    manual de init/shutdown em loop, sem crescimento de handles).

- [ ] **M2-T2 — Abrir e decodificar um arquivo**
  - **Arquivos:** `src/audio.h`, `src/audio.cpp`.
  - **O que fazer:**
    - `bool Audio_Load(const wchar_t* path);` usando `ma_sound_init_from_file_w`
      (ou equivalente) associado ao `ma_engine` — miniaudio decodifica
      MP3/WAV/FLAC nativamente.
    - OGG via `stb_vorbis`: como o miniaudio não decodifica Vorbis
      nativamente, implementar um `ma_decoding_backend` customizado
      usando `stb_vorbis` (miniaudio tem exemplos de decoder customizado).
      Se a integração não for óbvia, consultar MCP context7 (doc do
      miniaudio sobre "custom decoders") antes de tentar às cegas.
    - Expor `double Audio_GetDurationSeconds();` a partir do sound
      carregado.
  - **Testes:** teste unitário em `tests/test_audio_duration.cpp` (ou
    `.c`): carregar um arquivo de amostra curto e conhecido (colocar um
    `.wav` pequeno gerado/sintético em `tests/fixtures/`, sem depender de
    arquivos externos com direitos autorais) e checar que
    `Audio_GetDurationSeconds()` bate com o valor esperado dentro de uma
    tolerância pequena (ex.: 50 ms). Esse teste roda offline, sem precisar
    de device de áudio real (miniaudio permite decodificar sem tocar).
  - **Pronto quando:** o teste de duração passa para pelo menos WAV (formato
    mais simples de gerar como fixture); MP3/OGG/FLAC testados manualmente
    com arquivos reais do desenvolvedor.

- [ ] **M2-T3 — Play / pause / stop / posição**
  - **Arquivos:** `src/audio.h`, `src/audio.cpp`.
  - **O que fazer:**
    - `void Audio_Play(); void Audio_Pause(); void Audio_Stop();` usando
      `ma_sound_start`/`ma_sound_stop`, com estado próprio (`enum` Playing/
      Paused/Stopped) para a UI consultar.
    - `double Audio_GetPositionSeconds();` via `ma_sound_get_cursor_in_seconds`
      (ou equivalente).
    - "Stop" reseta a posição para 0 (diferente de pause); confirmar
      comportamento com `ma_sound_seek_to_pcm_frame(sound, 0)`.
    - Nenhuma dessas funções pode ser chamada de dentro do callback de
      áudio (ver regra em `AGENT.md`) — elas rodam na thread da UI/lógica,
      chamando a API do miniaudio, que é thread-safe para isso.
  - **Testes:** teste unitário cobrindo transições de estado (Stopped →
    Playing → Paused → Playing → Stopped) sem precisar de device real,
    usando um sound carregado em memória/nulo se o miniaudio permitir
    device de teste, ou mockando o estado interno caso a API real exija
    hardware — decidir a abordagem mais simples que ainda testa a máquina
    de estados de verdade (não só os `enum`s soltos).
  - **Pronto quando:** teste de transição de estados passa; manualmente,
    play/pause/stop funcionam ouvindo o áudio.

- [ ] **M2-T4 — Ligar à UI: abrir arquivo, play/pause/stop**
  - **Arquivos:** `src/mainwnd.cpp`, `src/app.cpp`.
  - **O que fazer:**
    - Menu ou botão temporário "Abrir arquivo" chamando
      `GetOpenFileNameW` com filtro para `.mp3;.wav;.flac;.ogg`.
    - Três botões mínimos (ainda sem arte final — placeholders) para
      play/pause/stop, desenhados na janela do M1, chamando as funções de
      `audio.h`.
    - `WM_TIMER` (ou `SetTimer` de baixa frequência, ex. 250ms) para
      invalidar a região de tempo/posição e forçar redraw enquanto toca —
      isso antecipa o display LCD do M3, mas aqui só precisa existir o
      mecanismo de atualização periódica, não o desenho bonito.
  - **Testes:** manual.
  - **Pronto quando:** clicar em "abrir", escolher um MP3/WAV/FLAC/OGG,
    clicar play toca o áudio; pause pausa; stop para e volta ao início.

## Checkpoint da milestone

- [ ] Abrir um arquivo pelo diálogo funciona.
- [ ] Play toca o áudio.
- [ ] Pause pausa.
- [ ] Stop para e volta ao início.
- [ ] Testado manualmente com MP3, WAV, FLAC e OGG.
- [ ] Validado manualmente pelo usuário antes de seguir para M3.
