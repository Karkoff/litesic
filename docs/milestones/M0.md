# M0 — Fundação do projeto

**Depende de:** nada (primeira milestone)
**Checkpoint visual:** não — ainda não há app; cada tarefa é verificada por
compilar/existir, não por abrir janela.

## Objetivo

Deixar o repositório num estado em que `make` compila um `.exe` mínimo,
`Ctrl+Shift+B`/`F5` funcionam no VS Code, e as dependências de terceiros
(miniaudio, stb_vorbis) estão vendorizadas. Sem isso nenhuma milestone
seguinte pode começar.

## Tarefas

  - **Arquivos:** cria diretórios, sem código ainda.
  - **O que fazer:**
    - Criar `src/`, `third_party/`, `res/`, `docs/`, `tests/` (além de
      `.vscode/` e `.agent/` já existentes).
    - Criar `README.md` na raiz com: nome do projeto, uma frase de
      descrição, como compilar (`make`), como depurar (`F5`), link para

  - **Pronto quando:** todas as pastas listadas na seção "Estrutura de
    pastas esperada" do `AGENT.md` existem; `README.md` criado e commitado.

- [x] **M0-T2 — Vendorizar miniaudio e stb_vorbis**
  - **Arquivos:** `third_party/miniaudio.h`, `third_party/stb_vorbis.c`,
    `third_party/README.md`.
  - **O que fazer:**
    - Baixar a versão estável mais recente de `miniaudio.h` (single header,
      https://miniaud.io) e `stb_vorbis.c` (https://github.com/nothings/stb).
    - Criar `third_party/README.md` anotando: versão/commit de cada
      biblioteca, licença (MIT/Unlicense/domínio público — checar cada uma),
      e data do vendoring.
    - Criar `src/miniaudio_impl.c`: único `.c` do projeto que define
      `MINIAUDIO_IMPLEMENTATION` antes de incluir `miniaudio.h`, para não
      duplicar símbolos em outras translation units.
    - Se houver dúvida sobre como integrar stb_vorbis com miniaudio (decoder
      customizado vs. suporte nativo do miniaudio a Vorbis), consultar MCP
      context7 pela documentação do miniaudio antes de decidir.
  - **Testes:** um `tests/build_third_party_smoke.c` (ou alvo separado no
    Makefile) que só inclui os headers e compila, sem lógica — garante que
    a integração não quebra por conflito de macros.
  - **Pronto quando:** `third_party/` populado, licenças documentadas,
    `src/miniaudio_impl.c` compila isoladamente sem erro.

- [ ] **M0-T3 — Makefile**
  - **Arquivos:** `Makefile`.
  - **O que fazer:**
    - Alvo `all` (Release): compila `src/*.cpp` + `src/miniaudio_impl.c` +
      `third_party/stb_vorbis.c` + recursos (`res/app.rc`) para
      `build/LiteSic.exe`.
    - Flags: `-std=c++17`, `-D_WIN32_WINNT=0x0601`, `-DUNICODE -D_UNICODE`,
      `-municode` (entry point `wWinMain`), `-static` (linkar
      libgcc/libstdc++ estático; `msvcrt` já é do sistema).
    - Alvo `DEBUG=1`: adiciona `-g -O0 -DDEBUG`, sem `-static` se atrapalhar
      o gdb (ajustar se necessário).
    - Alvo `ARCH=32`: troca o toolchain para `i686-w64-mingw32-g++` (MINGW32).
    - Alvo `clean`: remove `build/`.
    - Alvo `test`: compila e roda os binários de `tests/` (pode começar
      vazio, só com o esqueleto do alvo).
    - Usar `windres` para compilar `res/app.rc` em `.res`/`.o` e linkar.
  - **Testes:** manual — `make` deve gerar `build/LiteSic.exe` a partir de
    um `WinMain` vazio (criado nesta tarefa só para validar o build, será
    substituído em M1).
  - **Pronto quando:** `make`, `make DEBUG=1`, `make ARCH=32` e `make clean`
    funcionam sem erro no terminal MSYS2 MINGW64/MINGW32.

- [ ] **M0-T4 — Configuração do VS Code**
  - **Arquivos:** `.vscode/tasks.json`, `.vscode/launch.json`,
    `.vscode/c_cpp_properties.json`, `.vscode/extensions.json`.
  - **O que fazer:**
    - `tasks.json`: tasks "Compilar (Debug)", "Compilar (Release 64 bits)",
      "Compilar (Release 32 bits)", "Limpar" — todas chamando
      `C:\msys64\usr\bin\bash.exe -lc "make ..."` (caminho documentado como
      ajustável no `AGENT.md`/`README.md`).
    - `launch.json`: configuração "Depurar LiteSic (gdb)" usando
      `miDebuggerPath` do MSYS2 MINGW64, `preLaunchTask` apontando para
      "Compilar (Debug)".
    - `c_cpp_properties.json`: `includePath` cobrindo `src/`, `third_party/`
      e os includes do MinGW; `compilerPath` para o `g++` do MSYS2;
      `cppStandard: c++17`; define `_WIN32_WINNT=0x0601`.
    - `extensions.json`: recomenda `ms-vscode.cpptools` (obrigatória) e
      `ms-vscode.makefile-tools` (opcional).
  - **Testes:** manual — `Ctrl+Shift+B` compila, `F5` abre o gdb e para em
    um breakpoint de teste no `WinMain`.
  - **Pronto quando:** os 4 arquivos existem e o fluxo Debug (`F5`) funciona
    fim a fim.

- [ ] **M0-T5 — Recursos: manifest, ícone, app.rc**
  - **Arquivos:** `res/app.rc`, `res/app.manifest`, `res/icon.ico`
    (placeholder).
  - **O que fazer:**

  - **Testes:** manual — abrir `build/LiteSic.exe` no Explorer mostra o
    ícone; `objdump` ou Process Explorer confirmam manifest embutido.
  - **Pronto quando:** exe gerado pelo `make` tem ícone e manifest
    corretos, sem exigir DLL fora do sistema.
